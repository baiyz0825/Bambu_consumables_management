# 架构

一台打印机在库里只有一行，序列号是唯一键。采集端同时只维持这一行的一个连接：局域网端口通就直连，否则走拓竹云上的同一序列号。

交互图：[system.html](diagrams/system.html)

## 组件

```mermaid
flowchart LR
  ui["前端"]
  api["后端"]
  db[("数据库")]
  col["采集器"]
  printer["拓竹打印机"]
  cloud["拓竹云 MQTT"]

  ui -->|"REST / SSE"| api
  api -->|"结算、查询"| db
  col -->|"原始上报与标准化事件"| db
  api -->|"每 2 秒读取新事件"| db
  printer -->|"8883 优先"| col
  printer -.->|"保持账号登录"| cloud
  cloud -.->|"同一序列号的 report"| col
```

| 部分 | 目录 | 做什么 |
|---|---|---|
| 前端 | `frontend/` | 页面、PWA、拍照识别、数字孪生（three.js）、合盘向导 |
| 后端 | `backend/` | REST、SSE、打印结束后扣库存、合盘算法（`app/plate_merger/`）、设备控制协议、HMS 码表 |
| 采集器 | `collector/` | 每台打印机一个 MQTT 连接，41 个标准化字段 + HMS 事件 |
| 数据库 | SQLite 或 PostgreSQL | 事件、打印机、库存、任务、合盘产物（`merged_artifacts`）。没有单独的消息队列 |

## 生产链路（合盘 → 下发 → 扣料）

```mermaid
flowchart TD
  files["已切片 3MF ×N"] --> upload["POST /plate-merger/upload"]
  upload --> analyze["analyze：盘数/时长/槽位统计"]
  analyze --> merge["merge：注入换盘码 + 元数据重写"]
  merge --> artifact["merged_artifacts 落库"]
  artifact --> dispatch["dispatch：FTPS 上传 + MQTT 启打"]
  dispatch -->|"gcode_file 匹配"| job["打印任务（自动关联）"]
  job --> settle["结束时按切片用量扣料"]
```

## 登录与合并

```mermaid
sequenceDiagram
  participant 设置页
  participant 后端
  participant 拓竹登录页
  participant 采集器

  设置页->>后端: 从当前页面发起登录
  后端->>拓竹登录页: 打开官方登录页，回调指向本系统
  拓竹登录页->>后端: 带回 ticket
  后端->>后端: 换成令牌，按序列号对齐已有打印机
  采集器->>采集器: 直连失败时用这份令牌订同一序列号
```

从哪一页点的登录，回调就回到哪一页。令牌加密存在 `bambu_cloud_sessions`，不写进打印机表。打印机表只增加「当前通路」：局域网或云端。

## 扣库存

```mermaid
flowchart TD
  report["打印机 report"] --> raw["raw_events"]
  raw --> norm["normalized_events"]
  norm --> job["打印任务"]
  job --> settle{"结束时能对上库存？"}
  settle -->|绑定或颜色匹配| stock["扣这一条库存"]
  settle -->|对不上| pending["任务详情里待补录"]
```

云端和局域网读到的是同一类上报，所以扣库存的规则不用分两套。
